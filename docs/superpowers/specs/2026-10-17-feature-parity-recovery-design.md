# 猜数字游戏原版功能恢复与联机演进设计

日期：2026-10-17  
状态：已确认设计，待制定实施计划

## 1. 背景与目标

当前 React 版本优先完成了代码分层、可测试的游戏核心和未来联机扩展基础，但交付范围缩减为第一阶段单机版，导致原版中的本机账号、积分等级、排行榜、联机中心、好友与 PK，以及部分视觉效果缺失。自动测试只验证了缩减后的范围，不能证明原版体验得到保留。

本次补救以“原版功能完整度”为硬性验收标准，在保留现有工程结构和后续安全联机能力的前提下，恢复原版的功能、界面和交互。修复期间保留当前可运行版本，只有新版本通过完整验收并得到用户确认后才替换。

## 2. 已确认的产品原则

1. 采用渐进恢复方案：继续使用现有 React 工程，逐项恢复原版能力，不临时嵌回整份旧 HTML，也不回退到只维护原始单文件。
2. 原版外观和交互是基准，目标尽量接近 1:1；允许保留必要的手机适配、键盘操作和减少动态效果支持。
3. 第一轮补救同时恢复联机中心界面和原版接口兼容能力，即使当前仓库还没有可用服务器。
4. 不迁移旧 `file://` 页面产生的浏览器本地数据；修复版从新数据开始。
5. 本机账号与在线账号严格区分，避免用户误认为本机账号可以跨设备登录。
6. 最终公网联机以小范围朋友测试为目标，优先选择维护少、成本低的托管方案。

## 3. 范围拆分与交付顺序

### 3.1 版本一：恢复单机、本机账号与原版视觉

- 恢复原版页面结构、用户信息、等级进度、主题、弹窗和动画。
- 保留并完善当前游戏核心、移动端适配和无障碍能力。
- 恢复游客、本机注册、登录、退出、多账号独立数据、积分、等级、历史记录和本地排行榜。
- 恢复原版祝福语、结算表现、彩带和主题持久化。

### 3.2 版本二：恢复联机中心与原版接口兼容

- 恢复服务器地址设置、连接检测、在线注册登录、好友、好友申请、在线状态和 PK 邀请。
- 提供独立的原版接口适配层，不把旧接口约束散落到页面组件中。
- 在没有服务器、连接超时或凭证失效时给出明确状态，不影响单机游戏。
- 使用模拟服务器完成全流程自动化测试，并用兼容服务器进行契约验证。

### 3.3 版本三：建设并部署安全的公网联机服务

- 建设服务器权威的游戏、账号、好友、战绩和积分系统。
- 部署公开网页、持续运行的服务端和托管数据库，启用 HTTPS。
- 支持小范围朋友通过不同设备在线 PK、掉线重连和结果同步。
- 具体云平台在进入部署阶段时，根据当时的价格、免费额度和访问情况重新核实后选择。

三个版本分别制定规格、计划和验收，避免把本地功能恢复、兼容客户端和新服务端一次性塞入一个超大改动。

## 4. 功能验收矩阵

### 4.1 游戏本体

- 每局生成合法目标数字，支持输入猜测和回车提交。
- 正确提示偏大或偏小，并随有效猜测缩小可猜范围。
- 正确处理空输入、非整数、越界数字和重复数字。
- 显示已用或剩余次数、猜测记录和当前范围。
- 支持重新开始，且新旧局状态不串联。
- 提供原版五种主题并记住当前选择。
- 按原版规则根据猜中次数计算祝福语和积分。
- 胜利时显示彩带和过渡动画；系统启用减少动态效果时自动简化。

### 4.2 本机账号与进度

- 未登录时可以使用游客模式。
- 支持本机注册、登录和退出。
- 不同本机账号分别保存积分、等级、胜场和游戏记录。
- 等级采用原版十级门槛：`0、1、3、7、15、31、63、127、255、511`。
- 等级进度展示与实际积分一致，达到门槛后及时升级。
- 本地排行榜按积分排序，并按原版规则使用胜场等字段处理同分。
- 本地数据损坏、字段缺失或版本不兼容时安全降级，不导致白屏。
- 界面始终明确显示游客、本机账号或在线账号状态。

### 4.3 联机中心兼容客户端

- 可保存、修改和验证服务器地址。
- 可检测服务器可用状态，并区分未配置、连接中、在线、超时和错误。
- 支持在线注册、登录、退出和会话恢复。
- 支持添加好友以及查看、接受、拒绝好友申请。
- 显示好友在线或离线状态。
- 支持发起、接收、接受和拒绝 PK 邀请。
- 匹配成功后双方进入同一局，并看到一致的比赛状态和结果。
- 处理网络中断、轮询失败、登录过期、比赛超时和服务器关闭。
- 不可用的在线能力不会阻断单机游戏。

### 4.4 原版界面还原

- 恢复顶部操作按钮、用户信息区、等级进度、主题入口、游戏卡片和各类弹窗。
- 配色、间距、圆角、阴影、字体气质和动效尽量对齐原版。
- 手机端不能出现重要控件遮挡、横向溢出或无法输入。
- 所有主要操作可用键盘完成，焦点状态清晰，状态变化具有可读提示。

## 5. 软件结构

### 5.1 保留的基础

- 继续以现有 React 应用作为页面载体。
- 保留独立游戏核心作为规则唯一来源，页面不重复实现判定逻辑。
- 保留一键启动入口及当前构建、测试体系。

### 5.2 新增的边界

- `local-profile`：本机账号、当前会话、游客状态和数据版本升级。
- `progression`：积分、等级、祝福语和进度计算。
- `ranking`：本地排行榜排序与展示模型。
- `online-client`：统一的在线能力接口。
- `legacy-online-adapter`：只负责将统一接口映射到原版服务器协议。
- `social-and-pk`：好友、申请、邀请、比赛状态机和错误恢复。
- 页面组件：登录注册、个人信息、排行榜、联机中心、好友和 PK 弹窗；组件只展示状态并触发动作。

各模块通过明确的数据结构通信。替换兼容服务器为正式服务器时，页面和单机模块不需要重写。

## 6. 数据流与存储

### 6.1 本机数据

- 主题和界面设置按浏览器保存。
- 本机账号索引、当前本机会话及每个账号的积分、等级和历史记录按版本化结构保存。
- 本机密码不保存明文，只保存处理后的摘要；界面明确提示本机账号不是安全网络身份，不应复用重要密码。
- 所有读取都经过结构校验和默认值补全。无法恢复的数据被隔离，并安全回退到游客状态。
- 不读取或迁移旧单文件 HTML 使用的存储键。

### 6.2 在线数据

- 在线好友、积分、排行、战绩和比赛状态以服务器返回为准。
- 在线会话具有有效期，失效后清理身份并引导重新登录。
- 正式部署使用 HTTPS；密码由服务器采用适合密码存储的算法处理。
- 本机账号数据不会自动上传或与在线账号合并。

## 7. 兼容策略与防作弊

联机客户端提供两种实现，但对页面暴露相同能力：

1. 原版兼容适配器用于恢复原联机流程并连接旧协议。
2. 正式联机适配器连接新的安全服务。

兼容适配器被限制在单独模块中。旧协议如果允许客户端直接报告胜负或积分，只作为兼容行为存在，不成为新服务端的安全模型。

正式联机服务遵循服务器权威原则：

- 服务器生成并保存目标数字。
- 客户端只提交猜测，不提交可信的胜负或积分结论。
- 服务器检查回合、次数、重复请求和比赛参与者身份。
- 服务器计算并持久化比赛结果、积分变化和战绩。
- 重复提交采用幂等处理，断线重连后从服务器恢复比赛状态。

## 8. 异常与降级处理

- 单机存储异常：提示本机数据需要重建，保留游戏可用性。
- 服务器未配置：联机入口显示配置引导，不发起无意义请求。
- 服务器离线或超时：显示可重试状态，不清除本机游戏进度。
- 在线凭证失效：退出在线身份并保留本机身份。
- 好友或邀请状态过期：刷新服务器状态并显示可理解的结果。
- 比赛中断：正式服务端保留短期比赛状态；可重连则恢复，超时则由服务器结算或作废。
- 未知错误：记录可诊断信息，用户界面显示安全、简洁且可恢复的提示。

## 9. 公网部署方案

小范围朋友测试采用以下逻辑结构：

- 托管静态网页负责分发游戏客户端。
- 持续运行的托管应用或容器负责 HTTP 和实时联机通信。
- 托管关系型数据库保存账号、好友、积分、战绩和比赛摘要。
- 平台或自有域名提供 HTTPS 访问。
- 自动部署配置、环境变量模板、数据库初始化和备份说明随项目交付。

用户只需在正式部署时注册选定平台账号、按需绑定支付方式、决定是否购买域名，并在官方页面完成登录和最终授权。账号密码、验证码和支付信息不通过聊天传递。

第一版公网服务面向少量朋友，不建设大型大厅、复杂自动匹配、观战、语音或商业化系统。

## 10. 测试与验收

### 10.1 自动化测试

- 游戏核心：范围收缩、重复猜测、局面结束和重新开始。
- 进度系统：每个等级门槛、积分累加和祝福语分档。
- 本机账号：注册、登录、退出、多账号隔离、损坏数据恢复。
- 排行榜：积分、胜场和稳定排序。
- 在线客户端：请求格式、响应映射、超时、错误和凭证失效。
- 社交与 PK 状态机：好友申请、邀请、接受、拒绝、开始、结束和断线。
- 页面流程：游客游戏、本机登录游戏、排行榜、主题、联机中心和模拟 PK。

### 10.2 人工验收

- 对照原版逐项检查功能矩阵，记录通过、失败和证据。
- 对照原版检查桌面与手机页面的布局、弹窗、主题和动画。
- 在 Windows 上验证一键启动，禁止以直接打开构建入口文件作为标准使用方式。
- 公网版本使用两台不同设备和两个在线账号完成一场完整 PK。
- 验证服务器停机、网络中断和会话过期后仍能继续单机游戏。

### 10.3 发布门槛

每个版本只有同时满足以下条件才能交付：

1. 对应范围的功能对照表没有缺项。
2. 自动测试全部通过。
3. 人工实际操作通过。
4. 当前稳定版本仍可恢复。
5. 用户确认后才进入下一版本。

## 11. 非目标

- 不迁移旧单文件页面的本地账号或游戏数据。
- 不在第一轮补救中一次性完成正式公网服务端。
- 不为小范围测试提前建设大型匹配大厅、观战、聊天、语音、支付或反作弊风控平台。
- 不进行与原版功能恢复无关的全面重构。

## 12. 成功标准

补救成功不以“能构建”或“现有测试通过”为唯一标准，而以以下结果为准：

- 原版功能在相应交付版本中全部可见、可操作并通过对照验收。
- 外观与交互保持原版辨识度，同时桌面、手机和键盘操作正常。
- 单机、本机账号和在线账号边界清晰，网络故障不会破坏单机体验。
- 旧协议兼容逻辑被隔离，正式联机由服务器权威判定结果与积分。
- 最终可向少量朋友提供一个能够跨设备访问并在线 PK 的 HTTPS 地址。
