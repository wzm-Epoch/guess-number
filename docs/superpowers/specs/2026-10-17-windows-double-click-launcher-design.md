# Windows 双击启动器设计

## 1. 目标

为当前 React + Vite 猜数字项目提供一个面向普通 Windows 用户的双击入口。用户只需双击仓库根目录中的 `启动游戏.cmd`，即可完成环境检查、首次依赖安装、开发服务器启动和浏览器打开，不再直接打开 `apps/web/index.html`。

## 2. 范围

本次新增：

- 根目录双击入口 `启动游戏.cmd`。
- 负责实际启动流程的 `scripts/start-game.mjs`。
- 启动器自动化测试。
- README 中的双击启动说明。

本次不新增桌面快捷方式、不打包独立可执行文件、不修改游戏业务逻辑，也不将服务暴露到局域网或公网。

## 3. 启动流程

1. `启动游戏.cmd` 切换到自身所在的项目根目录，并设置 UTF-8 控制台编码。
2. 启动入口检查 `node` 和 `npm` 是否可用；缺失时显示中文错误并等待用户确认后退出，避免窗口闪退。
3. `scripts/start-game.mjs` 检查 Node.js 主版本是否满足项目声明的最低版本 24。
4. 如果根目录不存在 `node_modules`，启动器执行 `npm ci`，严格按 `package-lock.json` 安装依赖；安装失败时显示原因并停止。
5. 启动器从 5173 开始寻找本机回环地址上的可用端口。
6. 使用选定端口启动 Vite，绑定 `127.0.0.1` 并启用严格端口，避免意外对外暴露或打开错误地址。
7. 启动器轮询本地页面，确认服务可访问后调用 Windows 默认浏览器打开页面。
8. 服务继续附着在启动窗口中。用户关闭窗口或按 `Ctrl+C` 时，启动器同时终止其创建的开发服务器进程。

## 4. 文件职责

### `启动游戏.cmd`

只负责 Windows 双击体验：定位项目目录、检查基础命令、调用 Node 启动助手，以及在失败时保留窗口。该文件不包含端口扫描或服务轮询等复杂逻辑。

### `scripts/start-game.mjs`

封装可测试的启动流程：版本判断、依赖检查、可用端口选择、Vite 参数构造、服务就绪等待、浏览器打开和子进程清理。只使用 Node.js 内置模块，因此在依赖尚未安装时也能运行。

## 5. 错误处理

- Node.js 或 npm 缺失：给出安装 Node.js 24 或更高版本的中文提示。
- Node.js 版本过低：显示当前版本和最低要求。
- `npm ci` 失败：保留原始退出码，提示用户检查网络或 npm 输出。
- 端口查找失败：不启动服务，显示明确错误。
- Vite 提前退出或在限定时间内未就绪：不打开浏览器，终止残留子进程并返回失败。
- 浏览器打开失败：服务保持运行，并在窗口中显示可手动复制的本地地址。

## 6. 测试与验收

自动测试至少覆盖：

- Node.js 主版本解析及最低版本判断。
- 缺少 `node_modules` 时需要安装，存在时不重复安装。
- 从起始端口跳过已占用端口并选择可用端口。
- Vite 启动参数只绑定 `127.0.0.1`、使用选定端口并启用严格端口。
- 服务就绪成功、超时和子进程提前退出三种结果。

验收时运行完整单元测试、类型检查、代码检查和生产构建，并实际运行启动助手验证浏览器可访问本地页面。不得修改原始微信 HTML 附件。

## 7. 用户体验

用户只需要记住“双击根目录的 `启动游戏.cmd`”。第一次运行可能因安装依赖而稍慢；后续运行直接启动。启动窗口会持续显示服务日志，并明确提示“关闭此窗口或按 Ctrl+C 可停止游戏”。
